# Session log - 24 October 2026: VST3 and CLAP plugins

Asked: "turn the rest into a VST3 and CLAP plugin", built by GitHub Actions,
Mac only. Asked back what a plugin should do instead of Insert at Cursor; the
answer was play the block with the song and drag it out as a MIDI clip. The
decision is [0010](../decisions/0010-the-plugin-runs-the-window-script.md).

## What was built

- `plugin/`: JUCE 8.0.6, Lua 5.4.7, Dear ImGui 1.91.9b and
  clap-juce-extensions, cloned by `plugin/build.sh` (the GitHub archive host
  is blocked from the cloud container; git is not).
- The window script runs unchanged apart from the plugin's controls, which
  appear only where `Place` offers them.
- `tests/test_plugin.lua` runs the script as the plugin does. It reads the
  function list out of `ImGuiLua.cpp`, so it can only call what the plugin
  has. Bitten three ways before it was believed: with the block no longer
  handed over, with Escape closing the window again, and with
  `IsMouseDragging` taken out of the plugin.
- `plugin/test/smoke.cpp` makes the plugin with no host: the block reaches
  the audio thread, Play with the Song sends notes while a fake song plays and
  lets go of them all when it stops, Audition plays, state round-trips, and
  the window is painted to a PNG.

## What went wrong on the way

- The first painted window said "ImGui.Col_NavHighlight isn't available":
  Dear ImGui 1.91.4 renamed it `Col_NavCursor`; ReaImGui 0.9 still calls it
  the old name. The shim answers to both. Every other constant the scripts
  use was then checked against ImGui's own names; that was the only one.
- On GitHub's Mac the standalone window opened at its minimum size: setting
  the resize limits resized the editor, and `resized()` recorded that size
  before the remembered one was read.

## Not done

- Not seen in a DAW: dragging into a real arrange, MIDI routing in each
  host, keyboard focus inside a host's window, a Retina screen.
- No Audio Unit (Logic). It would be one word in `FORMATS` and `auval` in
  the workflow.
