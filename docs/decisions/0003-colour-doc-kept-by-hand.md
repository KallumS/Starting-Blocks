# 0003. `docs/COLOUR.md` is kept by hand, not generated

Taken 2026-09-19. Stands.

## Context

`docs/BLOCKS.md` is generated by `tools/blocks_md.lua`, which reads the engine's
tables directly, and `tools/test.sh` fails if it is stale. That pattern exists
because the catalogue is long, mechanical, and would rot silently.

When the colour scheme was written down, the obvious move was to do the same
thing: a `tools/colour_md.lua`, wired into the test runner. One was built. It
worked - it pulled the palette out of `tools/preview.lua`'s recording of the
real script, cross-checked the value both halves can see, and refused to emit a
file if R < G < B failed in any grey.

It was then removed, deliberately.

## Decision

`docs/COLOUR.md` is a **reference kept by hand**. The file says so in its second
paragraph, so nobody assumes otherwise:

> Unlike `BLOCKS.md`, this file is **not generated** - it is a reference, kept
> by hand. If you change a colour in `reascripts/Starting Blocks.lua`, change it
> here too.

## Consequences

The doc **can** drift from the code, and nothing will catch it. That is the
accepted cost. It is mitigated only by the note in the file and by the entry in
`CLAUDE.md`.

Anyone tempted to automate this should read the alternatives below first - the
generator was not rejected for being hard.

## Alternatives

**Generate it, like `BLOCKS.md`.** Built, then rejected. Three reasons:

1. The two files are not the same kind of thing. `BLOCKS.md` is a catalogue -
   long, mechanical, derived. `COLOUR.md` is a *guide*: most of its value is in
   the prose about why the greys are blue and what breaks if the ink is wrong,
   and none of that can be generated from a table of hex values.
2. The generator could not reach the whole palette anyway. `STEP`, `DIM` and
   `WARN` are all pushed as `Col_Text`, so a recording sees three pushes of one
   name and cannot tell them apart; `PLAYHEAD` is drawn only while auditioning.
   Those had to be read out of the source by pattern match - exactly the
   "regex's guess" that `blocks_md.lua`'s own header warns against.
3. It was more machinery than the problem deserved. Twenty values that change
   rarely, against a generator, a test-runner hook, and a second recording path
   to keep in step.

**Generate the tables and hand-write the prose**, splicing them. Rejected as the
worst of both: still all the machinery, plus a file that is half generated and
half not, with no clear line for a reader.
